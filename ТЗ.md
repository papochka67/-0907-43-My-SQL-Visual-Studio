# Техническое задание на приложение «ШагВГород»

## 1. Общие сведения
- **Наименование системы:** «ШагВГород» — приложение магазина обуви.
- **Тип:** десктопное приложение.
- **Стек:** C# (WinForms), MySQL.
- **Роли:** Гость, Клиент, Менеджер, Администратор.
- **Заказчик:** учебный проект, магазин обуви «ШагВГород».

## 2. Назначение и цели
Приложение автоматизирует каталог обуви, учёт остатков и оформление заказов.
Цель — единая точка работы с товарами и заказами без Excel и ручного учёта.

## 3. Требования к системе

### 3.1 Функциональные требования по ролям

**Гость**
- Просмотр каталога товаров (список, фильтры по категории, полу, размеру).
- Поиск по названию и бренду.
- Просмотр карточки товара: фото, цена, размеры, наличие.
- Переход к авторизации/регистрации.

**Клиент**
- Всё, что доступно Гостю.
- Регистрация и авторизация.
- Оформление заказа: выбор товара, размера, количества, адреса.
- Просмотр истории своих заказов и их статусов.
- Редактирование профиля (ФИО, телефон, адрес).

**Менеджер**
- Просмотр всех заказов и смена их статусов (Новый → В работе → Отправлен → Завершён/Отменён).
- Просмотр и корректировка остатков товаров.
- Просмотр карточек клиентов, связанных с заказами.
- Формирование простого отчёта по заказам за период.

**Администратор**
- Всё, что доступно Менеджеру.
- CRUD товаров, категорий, брендов, размеров.
- CRUD пользователей и назначение ролей.
- Просмотр логов действий (кто и что изменил).

### 3.2 Нефункциональные требования
- **Платформа:** Windows 10/11, .NET (WinForms).
- **БД:** MySQL 8.x, доступ через параметризованные запросы.
- **Производительность:** отклик интерфейса на типовые операции — до 1 сек на демо-данных (до 5 000 товаров).
- **Безопасность:** пароли хранятся в виде хеша; доступ к функциям — по роли.
- **Надёжность:** операции оформления заказа и изменения остатков — в транзакциях.
- **Удобство:** единый стиль форм, валидация ввода, информативные сообщения об ошибках.
- **Локализация:** русский язык интерфейса.

## 4. Состав и структура системы (модули)
1. **Модуль авторизации и пользователей** — вход, регистрация, роли, профиль.
2. **Модуль каталога** — список товаров, фильтры, поиск, карточка товара.
3. **Модуль склада** — остатки, размерная сетка, корректировки.
4. **Модуль заказов** — корзина/оформление, статусы, история.
5. **Модуль администрирования** — CRUD товаров, категорий, пользователей.
6. **Модуль отчётов** — выборка заказов за период, простая статистика.
7. **Модуль логирования** — запись ключевых действий пользователей.

## 5. Требования к данным
- **Пользователи:** id, логин, хеш пароля, ФИО, телефон, email, роль, дата создания.
- **Товары:** id, название, бренд, категория, пол, цена, описание, фото (путь), активность.
- **Размеры и остатки:** товар_id, размер, количество на складе.
- **Заказы:** id, клиент_id, дата, статус, сумма, адрес доставки.
- **Позиции заказа:** заказ_id, товар_id, размер, количество, цена на момент заказа.
- **Категории/бренды:** справочники с уникальными названиями.
- **Логи:** id, пользователь_id, действие, объект, дата/время.
- **Целостность:** внешние ключи между заказами, позициями и товарами; запрет отрицательных остатков.
